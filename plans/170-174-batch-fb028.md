**The routes and their evidence.** A client process started after the update lists the new
text in a fresh context (M81, verified). A process started after the update by `--resume` shows
its old record until a compaction and the new text after it (`5bc5eab5`: resume 06:09Z,
compaction 20:33Z, record 20:39Z; one case). The same process after a reload shows the old text
before and after a compaction (FB-028; one case). The same process without a reload shows the
process's text (M80's control). **The maintainer's model, labelled as such:** the client builds
its tool listing when its process starts; a compaction rewrites the record from that listing;
a reload restarted the server and the hooks and did not rebuild the listing.

**Researched (a docs agent over `code.claude.com/docs`; the GitHub changelog and issues were out of
its reach):** a reload "reconnects" a server whose configuration changed (the plugin root moves
with the version) and nothing is stated on re-fetching the tool definitions a session already
lists; a `--plugin-dir` plugin sharing an installed plugin's name "loads the session-only copy
for that session and skips the installed one", recorded by one line in the `--debug` log; tool
names `mcp__plugin_<plugin>_<server>__<tool>`; `mcp__<server>__*` is an accepted allow glob;
`dontAsk` is the documented mode for scripts ("anything that would prompt is denied"); the
empty `--setting-sources` value is undocumented for the CLI (the SDK's `[]` is documented);
`--max-budget-usd` on a subscription is undocumented; `SessionStart` events "are always
included" in `-p`. Every flag claim is checked by plan 172's probe.
