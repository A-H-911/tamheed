## Oracles and the tie-break

| Claim class | Oracle |
|---|---|
| Methodology (stages, human points, loops, lifecycle, actors) | `plugins/tamheed/references/workflow.md`, `governance.md`, the owning SKILL.md — quoted by line |
| Mechanism (what the server refuses, flushes, journals, fills) | `plugins/tamheed/server/tamheed_server.py` + `db/schema.sql` triggers, source line **and** a runtime witness on a tmp package |
| Structure (columns, params, rule ids, counts) | engine-derived by `docs/guide/extract.py` + the families witness (W rows) |
| Visualization | the capture, named by geometry; fix in `docs/guide/diagrams.py` / `guide.css` |

Tie-break: the engine wins for a sentence labelled *enforced*; the references win for *expected*; a
disagreement between them is a docs defect (D rows) for a separate `docs:` commit. `README.md`,
`docs/*.md`, CHANGELOG are never the oracle.

Verdicts: `wrong` · `over-broad` · `right` · `unclear` · `design choice`. Fix targets: a `content.py` id
(EN + AR), a `diagrams.py` model, a `guide.css` rule, a `render.py` block, `extract.py`, or `docs:`.

`http://127.0.0.1:8765/index.html?r=<n>` (bump after every rebuild); 1280×900 viewport chunks, dark;
light for every diagram and table; 390 px for every diagram and table; sticky header hidden and
`svg.dia .draw/.step` forced to end state by injected CSS; one reading-speed pass per diagram round.
