Every measurement that the install docs quote, verbatim from the shell. Claude Code 2.1.294 on

machine's `~/.claude/plugins/installed_plugins.json`.

## 2026-10-09: the two scratch runs that decided the design

A local-scope record at 6.2.1 was installed in a scratch folder beside the user record at 6.2.0. One
headless session in that folder asked `server_info` for its version:

```
user  | 6.2.0 | (no project)                  | cache\tamheed\tamheed\6.2.0
local | 6.2.0 | C:\Users\ahammo\Repos\tamheed | cache\tamheed\tamheed\6.2.0
local | 6.2.1 | <scratch>                     | cache\tamheed\tamheed\6.2.1
server_info().version in the scratch session: 6.2.0
```

The user record won the load. Then, in the same folder, with the installed plugin set `false` in the
folder's local settings and `--plugin-dir` on the marketplace clone (6.2.1): `6.2.1`. With the
installed plugin set `true` and the same flag: one server, `plugin:tamheed:tamheed 6.2.1`. The
`--plugin-dir` copy shadows the installed one (the vendor's "Name conflicts" item 2 agrees). The
scratch record was removed after (`uninstall --scope local`); the `6.2.1` cache folder stayed.

(`known_marketplaces.json`, the clone under `~/.claude/plugins/marketplaces/tamheed`), declared by the

through their prompts). Two mentions of tamheed remain in the user settings and are not install state:
the `TAMHEED_HOOK_LOG` environment variable (the operator's opt-in hook trace, plan 136) and an
auto-mode allow phrase ("tamheed MCP calling"). Both are the operator's own conveniences, named in
the review.
